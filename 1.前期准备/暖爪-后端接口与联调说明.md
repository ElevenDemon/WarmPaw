# 暖爪后端接口与联调说明

后端目录：`D:\CodeDemo\petDemo\3.petSpringboot`。启动方法见该目录 README。接口参数、校验约束及完整路径以运行后的 Swagger 为准：`http://localhost:8080/swagger-ui.html`；机器可读文档：`/v3/api-docs`。

## 公共约定

默认超级管理员为 `admin / admin123456`，首次启动自动创建，拥有全部后台权限。可在首次创建前通过BOOTSTRAP_PASSWORD覆盖初始密码；重复启动不会重置已有账号密码。

接口根地址 `http://localhost:8080/api`。请求/响应使用 JSON。成功响应：

```json
{"code":0,"message":"ok","data":{"list":[],"total":0,"page":1,"size":10}}
```

分页接口使用 page（从1开始）、size（1–100），其他接口 data 可为对象、数组、主键或布尔值。业务错误保留对应HTTP状态码，响应code为相应状态码，message含失败说明，data为空时省略。400参数错误，401未登录，403权限不足，404记录不存在，409冲突，501预留功能未实现。

先调用 `POST /auth/login`，将 `data.token` 保存到客户端，请求头携带 `Authorization: Bearer <token>`。`GET /auth/me` 返回当前登录人；`POST /auth/logout` 注销当前令牌。角色含 OWNER、SITTER、ADMIN、SUPPORT、FINANCE，后台进一步按权限码限制。

DTO请求字段采用 camelCase；SQL报表和业务列表以数据库列名 snake_case 返回。前端应显式映射字段。金额为未格式化的元数值，页面自行显示人民币符号；百分比抽成为20表示20%，会员折扣0.9表示九折。时间使用ISO8601并带时区，例如 `2026-12-01T10:00:00+08:00`。ID是数据库bigint，前端不要生成自己的数据库ID。

## 原型后台页面对应

以下路径均相对 `/api`。通用后台分页接口为 `GET /admin/modules/{module}?page=1&size=10&keyword=&status=`，只允许服务器白名单模块。原型中的统一 `update({action,id})` 不能直接用于后端，写操作需调用具体接口并传完整DTO。

| Vue模块 | 查询与操作入口 |
|---|---|
| dash 工作台 | GET /admin/dashboard |
| order 订单 | modules/order；GET /orders/{id} |
| dispatch 派单 | modules/order?status=DISPATCHING；GET /admin/orders/{id}/eligibility/{sitterId}；POST /admin/orders/{id}/assign |
| audit 喂养师审核 | modules/audit 与 modules/sitter 同源档案；POST /admin/sitters/{id}/audit 审核入驻；modules/qualifications 查看分类资质，POST /admin/qualifications/{id}/audit 审核单项资质 |
| service 客服 | modules/service；会话接管、消息和关闭接口见Swagger |
| emergency 应急 | modules/emergency、modules/hospitals；PUT /admin/emergencies/{id}；POST /emergencies/{id}/consent |
| finance 财务 | modules/finance、modules/refund；POST /admin/settlements/batch-settle；演示退款 /admin/orders/{id}/demo-refund |
| member 会员 | modules/member、modules/plans、modules/benefits；/admin/plans、/admin/benefits/{id} |
| sitter 喂养师 | modules/sitter、modules/grades、modules/grade-revisions；/admin/grades/simulate、/admin/grades/estimate |
| user 宠主 | modules/user；PUT /admin/owners/{id}/status |
| coupon 优惠券 | modules/coupon、modules/coupon-logs；/admin/coupons；直发接口见Swagger |
| price 定价 | modules/price；PUT /admin/prices/{id} |
| review 评价投诉 | modules/review、modules/complaints；投诉处理接口见Swagger |
| msg 消息 | modules/msg；PUT /admin/notification-templates/{id} |
| system 系统权限 | modules/system、modules/roles、modules/staff；PUT /admin/roles/{role}/permissions；POST /admin/staff |
| dict 数据字典 | GET /admin/dictionary |

表格中 `modules/xxx` 的完整路径为 `/admin/modules/xxx`。详细的入参、请求方法和权限限制请在Swagger对应分组查看。

喂养师审核和信息页均使用sitter_profile主键作为档案ID，姓名和电话实时关联app_user，修改资料后两页查询均反映最新值。入驻审核列表包含全部档案（包括未提交资质的喂养师），可按状态筛选。分类资质按sitter_id关联档案，资质记录自身的id仅用于单项资质审核。

审核流程：先在“分类资质”中审核申请类目，再在“入驻审核”中通过入驻。通过入驻要求所有申请的基础类目均已认证且未过期；通过更新共享档案为ACTIVE，驳回为REJECTED，审核意见写入操作审计。仅PENDING/REJECTED状态可执行入驻审核，停用与休息状态由档案管理控制。高风险类目继续独立审核实操资格。

## 下单与服务闭环

1. 宠主注册或登录后，使用 `/owner/pets`、`/owner/addresses` 创建资料。
2. 从 `GET /public/catalog` 获取服务价格、会员方案等当前配置，使用真实服务ID。
3. 创建订单，后台重新计价并保存协议、地址、宠物和价格快照。requestKey在同一宠主下保证幂等，重试沿用同一键。

```json
{
  "requestKey":"checkout-20261201-001",
  "addressId":1,
  "petIds":[1],
  "serviceStart":"2026-12-01T10:00:00+08:00",
  "serviceEnd":"2026-12-01T10:30:00+08:00",
  "items":[{"serviceId":1,"quantity":1}],
  "agreementVersion":"v1",
  "agreementAccepted":true,
  "authorizationScope":"仅限本次上门喂养服务",
  "notes":"请关好门窗"
}
```

示例ID需替换为当前账号实际数据，serviceId须对应BASE服务。预约时间必须在未来、开始早于结束且最长12小时。优惠券可选传 couponId，后端校验有效期、门槛与服务范围。

演示流程：`POST /orders/{id}/demo-pay` → 管理员人工派单 → 喂养师 accept → checkin → 更新 checklist → 保存 media → complete → 宠主 review。标准清单代码为 FEED、WATER、CLEAN、PLAY、DOOR；陪玩须至少10分钟，unit为MINUTE。完成必须有录像元数据。

| 状态 | 含义 |
|---|---|
| PENDING_PAYMENT | 待付款 |
| DISPATCHING | 待人工派单 |
| PENDING_ACCEPT | 等待喂养师接单，60秒超时回到待派单 |
| ACCEPTED | 已接单待上门 |
| SERVICING | 服务中 |
| COMPLETED | 已完成 |
| CANCELLED | 已取消 |
| REFUNDED | 已退款 |

人工派单校验服务半径、档期、容量和资质；抽成在首次派单时冻结，改派保留历史抽成快照。取消释放锁券，支付核销券，支付和会员赠券按幂等处理。紧急送医必须先取得宠主明确授权，再提供医院并推进工单。

## 本次实现边界

AI本次暂不实现，`POST /admin/ai/dispatch`、`/ai/report`、`/ai/chat`、`/ai/route` 返回HTTP501。服务完成后报告保存原始服务快照，状态为PENDING_AI。后续Python服务可接入派单建议、报告生成、聊天与路线能力；目前没有实现外部AI调用或回调消费，前端应展示待处理状态。

演示支付和演示退款仅在DEMO_ENABLED=true时开放，没有真实支付网关或支付回调。媒体接口仅保存对象存储键等元数据，没有实现文件上传、视频转码和签名播放URL。通知为站内通知，微信/短信、实时IM、地图路线与远程存储均需后续集成。

Vue当前仍是页面原型和mock数据，本次未替换前端请求层。联调时需增加API客户端、登录态、列表字段映射和状态文案，并处理401/403/501。AI入口在界面中应标注尚未开放。
