# 暖爪 PostgreSQL 数据库表结构设计

依据：PRD v1.4、2.petVue后台原型；实现：Spring Boot 3.5.7 + MyBatis-Plus 3.5.14，Java 21。

## 1. 数据库及初始化

- 数据库：pet_demo，默认localhost:5432，账号postgres，密码root；可由DB_URL/DB_USERNAME/DB_PASSWORD覆盖。
- 共37张业务表，不含Flyway版本表。所有主键bigint identity；所有金额numeric，单位元；时间timestamptz存储绝对时刻，业务档期按Asia/Shanghai计算。
- 正常运行由Flyway自动顺序执行V1/V2/V3/V4。V4为全部业务表和字段写入PostgreSQL原生中文注释，可在数据库客户端直接查看。配套《暖爪-数据库初始化.sql》只供空库审阅、独立初始化使用；二者选择一种，不能先手工建表再直接运行Flyway。
- 不保存明文登录密码或Bearer令牌。媒体表仅保存对象元数据，不含录像二进制；AI报告保存待处理数据，不调用模型。

## 4. 完整字段、约束与索引

数据库约束定义为最终准确依据；API层另有业务验证。外键默认NO ACTION，保留订单与资金审计历史。

### app_user · 统一账号

| 字段 | 类型 | 允许空 | 默认值 | 说明 |
|---|---|---|---|---|
| id | int8 | 否 | IDENTITY ALWAYS | 自增主键 |
| username | varchar(64) | 否 | — | 登录账号 |
| password_hash | varchar(100) | 否 | — | BCrypt密码摘要，不返回前端 |
| name | varchar(32) | 否 | — | 名称 |
| phone | varchar(11) | 是 | — | 手机号码 |
| role | varchar(20) | 否 | — | 账号角色 |
| status | varchar(20) | 否 | 'ACTIVE'::character varying | 业务状态，枚举见本表CHECK约束 |
| created_at | timestamptz | 否 | now() | 创建时间 |
| updated_at | timestamptz | 否 | now() | 最后更新时间（由业务显式更新） |

约束（含主键、唯一键、外键、CHECK）：

~~~sql
app_user_created_at_not_null: NOT NULL created_at
app_user_id_not_null: NOT NULL id
app_user_name_not_null: NOT NULL name
app_user_password_hash_not_null: NOT NULL password_hash
app_user_phone_key: UNIQUE (phone)
app_user_pkey: PRIMARY KEY (id)
app_user_role_check: CHECK (((role)::text = ANY ((ARRAY['ADMIN'::character varying, 'SUPPORT'::character varying, 'FINANCE'::character varying, 'OWNER'::character varying, 'SITTER'::character varying])::text[])))
app_user_role_not_null: NOT NULL role
app_user_status_check: CHECK (((status)::text = ANY ((ARRAY['ACTIVE'::character varying, 'BLOCKED'::character varying])::text[])))
app_user_status_not_null: NOT NULL status
app_user_updated_at_not_null: NOT NULL updated_at
app_user_username_key: UNIQUE (username)
app_user_username_not_null: NOT NULL username
~~~

索引：

~~~sql
CREATE UNIQUE INDEX app_user_phone_key ON public.app_user USING btree (phone);
CREATE UNIQUE INDEX app_user_pkey ON public.app_user USING btree (id);
CREATE UNIQUE INDEX app_user_username_key ON public.app_user USING btree (username);
~~~

## 5. 状态、事务和快照规则

订单主路径：PENDING_PAYMENT → DISPATCHING → PENDING_ACCEPT → ACCEPTED → SERVICING → COMPLETED。取消到CANCELLED、退款到REFUNDED。拒单/60秒未响应回DISPATCHING，人工重新派单；30分钟未支付自动取消并释放券。服务开始后不允许普通取消。

券路径：AVAILABLE → LOCKED → USED；未支付取消释放为AVAILABLE，过期变EXPIRED。主动领取依次校验启用及渠道、时间窗、人群、限领、库存、风控，最后入账；失败日志与成功日志都持久化。后台直发独立于领取库存。

订单创建锁宠主账号及用户券；同宠主request_key唯一；服务明细、地址、宠物、会员折扣、券金额和授权协议冻结。抽成在首次明确分配喂养师时冻结，改派不改变，避免历史财务数据随等级配置漂移。

人工派单先锁订单再锁喂养师，核对七天档期、容量、重叠、距离、账号状态、类目及高风险资质，不执行AI排序。完成服务、报告原始快照、结算和进出提醒同事务提交。

退款和批量结算都先锁订单再锁结算表；已结算订单禁止直接演示退款。结算基数为优惠后的实付金额，平台费按百分数四舍五入到分，其余归喂养师。

会员购买冻结套餐价格、期限及赠券数量，支付单唯一，重复演示支付不续期、不重复赠券；默认年度会员赠2张满60减20券。等级规则默认下一个半月结算期生效（每月1日或16日00:00），待生效版本独立存储，每15秒扫描执行。显式传入已到期effectiveAt可立即更新。

媒体登记后7天逻辑到期，访问接口校验订单归属；实际云存储自动删除、上传鉴权及签名播放尚待接入。站内消息在业务事务内写入；微信、短信、实时通信、真实支付和Python AI服务后续对接。
