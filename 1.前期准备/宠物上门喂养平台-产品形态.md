# 暖爪 · 宠物上门喂养平台 · 产品形态与功能设计

> 头脑风暴产出稿 · 待确认后再进入界面设计

---

## 一、一句话定位

**暖爪** —— 一个"自营/签约喂养师团队 + AI 智能调度与客服"的宠物上门喂养平台，解决宠主出门时宠物无人照看的痛点。核心用户通过小程序下单，喂养师通过小程序接单执行，运营团队通过后台管理数据与客服，官网做品牌展示与引流。

---

## 二、核心决策（已确认）

| 维度 | 决策 |
|------|------|
| 商业模式 | 自营/签约喂养师团队，平台派单为主，品质可控 |
| 匹配机制 | 日常自动派单 + 特殊需求（指定喂养师/特殊要求）可选 |
| 端形态 | 后台（数据+客服）+ 小程序（宠主/喂养师双角色）+ 官网（营销页） |
| App | 放到 2.0，暂不做 |
| AI 定位 | 作为产品差异化特色能力，分阶段融入 |
| AI 优先级 | 先做 A 智能派单 + B 智能客服 + C 智能喂养报告 + D 上门路线推荐；健康趋势暂缓 |

## 三、四端定位与功能清单

### 1. 官网（纯营销页 · 品牌 + 引流）

定位：不是交易入口，是"门面"。承接搜索流量、树立信任、引导扫码进小程序。

**核心板块**
- 首屏：品牌主张 + 核心痛点（"出门在外，宠物交给我们"）
- 服务介绍：喂养服务内容、流程、收费标准
- 喂养师展示：资质认证、背景介绍（建立信任）
- AI 能力展示：智能派单 / 智能报告，作为差异化卖点
- 覆盖城市 / 服务区域
- 用户评价 / 案例
- 底部：小程序码 + 引导语（"微信扫码，立即下单"）

**关键点**：SEO 友好（搜索"上门喂养 XX 市"能搜到）、移动端优先、全程引导到小程序。

---

### 2. 小程序（核心用户端 · 双角色）

小程序是唯一的"交易 + 执行"载体，宠主和喂养师通过同一小程序、不同身份进入。

#### 宠主端
- **注册/登录**：微信授权，绑定手机
- **宠物档案**：多只宠物管理（品种、年龄、性格、饮食禁忌、医疗信息、**既往病史**）
  - 补充：支持**异宠类目**（兔/鸟/仓鼠/龟），档案字段按物种差异化
- **下单**：
  - 选择宠物 → 选择服务时间（日期 + 每天频次）→ 选择服务内容（喂食/换水/铲屎/遛狗/陪玩/拍照）
  - **附加服务菜单化**：梳毛、剪指甲、驱虫、生骨肉备餐、擦眼/擦耳、喂药等，逐项勾选计费（借鉴小布在家）
  - 特殊需求：指定喂养师、附加要求（喂药、注意事项）
  - **应急服务入口**：可预约"24h 应急上门 / 紧急送医协助"（MVP 纳入）
  - 支付（微信支付）
- **订单管理**：查看订单状态、改期、取消、退款
- **喂养报告**：实时查看喂养师上传的图文报告（AI 生成）
- **喂养师主页**：查看喂养师资料、评分、评价、**个性化标签**（擅长宠物类型/可服务项）
- **评价体系**：订单完成后评价喂养师
- **客服**：AI 客服优先，人工客服兜底；**每单专属服务群**（宠主+喂养师+客服）实时图文播报

#### 喂养师端
- **身份认证**：实名 + 资质审核（分级审核，见机制决策）
- **任务中心**：接收派单通知（可限时接/拒），拒单后自动派下一位
- **任务执行**：
  - 开始/结束打卡（含定位/时间戳）
  - 按 checklist 勾选喂养动作（**动作量化标准**：陪玩≥10分钟、清洁食具、彻底清理猫砂及周边等）
  - 拍照/录视频记录宠物状态
  - 全程录像并上传云端（**可选服务直播**：宠主付费开直播，喂养师一键开播）
  - 异常情况上报（宠物不适、门锁问题等）
  - **应急送医流程**：异常时触发送医引导，推送就近合作医院清单
- **路线推荐**：当天多单时，AI 规划最优上门顺序与路线
- **档期管理**：设置可接单时间段
- **我的档案 · 编辑**（v1.3 补充）：姓名 / 手机号 / 擅长类目 / 常驻地址 / 所在区 / 服务半径 / 交通方式 / 备注可自行修改；认证等级、平台抽成、账号状态、每日档期由后台设定，此处只读。保存后与运营后台「喂养师档案 · 编辑」实时同源
- **收益查看**：接单记录、收入统计、提现
- **评分/评价**：查看宠主对自己的评价

---

### 3. 后台管理（运营大脑 · 数据 + 客服）

定位：给运营/客服/调度团队用的管理工具。

**核心模块**
- **数据看板**：订单量、GMV、活跃用户、喂养师接单量、区域分布
- **订单管理**：全部订单的查询、状态流转、异常订单处理
- **喂养师管理**：入驻审核、资质管理、排班、评分监控；**喂养师档案 · 编辑**（基本信息 / 资质结算 / 常驻地址 / 每日档期四段同屏，详见「九」）
- **宠主管理**：用户信息、宠物档案、订单历史
- **智能派单调度**：查看 AI 派单结果、人工干预/改派
- **客服工作台**：
  - AI 客服自动回复常见问题
  - 人工客服接管复杂问题
  - 会话记录、话术库
- **应急调度**：24h 应急订单受理、就近医院资源管理、送医跟进（MVP 纳入）
- **营销/内容**：优惠券（**直接发放 / 用户领取双通道**，详见「九」）、活动、官网内容管理（可选）
- **财务**：流水、抽成、喂养师结算、退款

## 四、AI 能力（"agent" 特色 · 分阶段）

### 阶段一（首发，与平台同步上线）

**A. AI 智能派单**
- 输入：宠主下单信息（位置/时间/宠物类型/特殊需求）+ 喂养师库（位置/评分/档期/擅长宠物类型）
- 输出：最优喂养师推荐 + 派单理由
- 关键逻辑：距离优先 × 档期匹配 × 评分权重 × 宠物类型匹配
- 价值：减少人工调度成本，缩短派单时间，提升匹配质量

**B. AI 智能客服**
- 自动回复高频问题：价格、服务范围、流程、改期、退款政策、宠物类型限制
- 人工客服兜底：AI 解决不了的自动转人工
- 价值：7×24 响应，降低客服人力成本

**C. AI 智能喂养报告**
- 输入：喂养师上传的照片 + 勾选的 checklist 数据 + 文字备注
- 输出：自动生成给宠主的图文报告（喂食量、状态描述、异常提醒、亲和语气）
- 定位：喂养师只需打勾 + 拍照 + 简单备注，AI 自动组织成结构化、语气统一的报告，喂养师无需写长文
- 语气原则：**温暖 + 克制**——让宠主安心，但不夸大、不做医疗断言（用"未见异常""进食正常"等事实性描述，避免"很健康"这类判断）
- 异常分级：
  - **轻微异常**（进食量略降等）：仅在报告中提示
  - **明显异常**（拒食、呕吐、受伤等）：即时触发预警，推送宠主 + 通知客服/平台介入
- 价值：提升报告专业度与一致性，减少喂养师写作负担，增强宠主信任

**D. AI 上门路线推荐**
- 场景：喂养师一天接多单时，AI 根据各订单地址 + 时间窗口，规划最优上门顺序与路线
- 输出：喂养师端展示当天任务时间轴 + 建议出行路线（就近/顺路排序），减少通勤时间
- 价值：提升喂养师单日接单效率，间接增加平台运力

### 阶段二（后续，暂不做）

- **E. 宠物健康趋势分析**：基于长期喂养记录，AI 分析饮食/健康趋势，主动提醒宠主（需数据积累，暂缓）
- 可能的延伸：AI 定价优化、宠物面部识别（自动识别宠物/剔除模糊照）、AI 风险预警升级等

## 五、核心业务流程

```
宠主下单（选宠物/时间/服务内容，签授权协议，选计费方式）
   │
   ▼
AI 智能派单 ──► 自动派给最优喂养师
   │              （特殊需求：宠主指定或人工干预）
   ▼
喂养师接单/执行：
   到门口 ──► 推送"即将进门"提醒 ──► 全程录像上传
   打卡 → checklist → 拍照 → 喂食/换水/铲屎等
   完成 ──► 推送"已离开"提醒
   │
   ▼
AI 生成喂养报告 ──► 推送宠主
   │
   ▼
宠主评价 → 订单完成 → 结算（按次/套餐/会员计费）
```

## 六、非目标（Anti-goals，明确不做）

- **不做 App**（2.0 再评估）
- **不做**宠主与喂养师的"自由抢单市场"（保持自营品质可控）
- **不做**宠物医疗诊断（AI 报告只做状态描述，不做医疗建议，规避合规风险）
- **不做**宠物健康趋势分析（D 暂缓）
- **不做**寄养、美容等其他宠物服务（先聚焦"上门喂养"这一件事）

## 七、核心决策（第二轮已确认）

| 维度 | 决策 |
|------|------|
| 品牌名 | **暖爪** |
| 首期覆盖 | **深圳**（试点城市，派单半径与招募均按深圳配置） |
| 收费模式 | **按次 + 套餐 + 会员** 三种并行（下单时可选） |
| 喂养师来源 | **平台招募**（开放入驻申请 → 审核 → 培训 → 认证） |
| 安全机制 | **进门全程录像并上传 + 进/出门消息提醒宠主** |

### 安全机制（信任核心，重点设计）

这是"暖爪"区别于竞品的信任基石，需贯穿下单与执行全流程：

- **进门前提醒**：喂养师到达门口、准备进门时，自动推送消息给宠主（"喂养师已到家门口，即将进门"）
- **全程录像**：进门后全程录像并实时/准实时上传云端，宠主可在订单详情回看
- **离开提醒**：喂养师完成服务、离开时，推送消息给宠主（含离开时间戳）
- **授权与协议**：宠主下单时签署上门服务授权协议（钥匙/门锁授权范围、宠物安全责任约定）
- **责任保障**：配套平台责任险/宠物意外险机制（需进一步落地）

## 八、收费模式设计（按次 / 套餐 / 会员）

**按次计费（基础）**
- 单价 = 基础服务费（按宠物数量、频次、服务内容）+ 附加项（遛狗/喂药/加时等）
- 适合：偶尔出门、短期出差用户

**套餐（频次打包）**
- 例：连续 3 天 / 7 天套餐，打包价低于单次累加
- 适合：长假出行、固定出差用户

**会员（长期权益）**
- 月卡/季卡/年卡，享折扣 + 优先派单 + 专属客服等权益
- 适合：高频用户，提升留存与复购

> 财务模块需支持：三种计费并存、叠加优惠券、退款、喂养师结算（含平台抽成）。

## 九、核心机制决策汇总（已确认）

### 喂养师入驻审核 —— 分级审核

- **基础类目**（喂食/换水/铲屎）：实名认证 + 培训考核，轻审核快速上线
- **高风险类目**（遛狗/喂药/攻击性宠物）：额外线下实操认证 + 背景核查
- 全流程：报名 → 资质初筛 → 培训考核 → 线下认证（按类目）→ 签约+保险 → 上线接单

### AI 智能派单 —— 可拒单的匹配制

- **喂养师可拒单**（限时），拒单后自动派给下一位；喂养师端为"接单通知"形态，非强制任务列表
- **指定喂养师不完全锁定**：宠主指定后该喂养师仍可拒单，拒单后回落 AI 派单（下单时需向宠主明示此预期）
- **派单考虑因素**（按权重）：位置距离 → 档期 → 宠物类型匹配 → 评分 → 熟悉度（回头客）→ 负载均衡；**AI 读取的是喂养师单一档案**（基本信息 / 资质结算 / 常驻地址 / 每日档期），不设独立的地址配置模块
- **特殊需求**（喂药/攻击性宠物/多宠）作为独立标签，只派给认证过相应能力的喂养师
- 后台调度员保留**人工改派**入口

### 喂养师档案 —— 单一档案 + 编辑原型（v1.3 补充）

- **归属原则**：常驻地址、经纬度、服务半径、交通方式、周一至周日逐日档期，以及资质、抽成、账号状态，都是**喂养师个人档案字段**，不单独拆成「服务地址设定」「档期配置」等模块。原型中已把原独立卡片收编为「喂养师档案 · 编辑」全宽面板。
- **四段同屏、一次保存**：① 基本信息（姓名 / 工号 / 手机号 / 加入时间 / 紧急联系人 / 头像 / 备注）→ ② 资质与结算（认证等级 / 账号状态 / 平台抽成 / 结算方式 / 擅长类目 / 评分 / 服务区域 / 合规资质）→ ③ 常驻地址与半径 → ④ 每日档期（当日地址 / 覆盖区域 / 时段 / 容量 / 休息日）。点「保存档案」整份提交，也可只提交 ③④ 段。
- **编辑入口 = 列表 → 编辑的主从视图**：列表行「编辑档案」、详情卡「✎ 编辑档案」、深链 `#/admin/sitter?edit=<工号>`。进入后列表与详情收起，编辑器独占一屏；顶部「← 返回列表 / 搜索定位 / ‹ › 顺序切换」，四段导航替代人员标签。返回时恢复列表并高亮刚编辑那一行。
- **不在编辑器里放人员下拉**：喂养师上百人时，下拉与人员 chip 都是全量枚举，和列表页的搜索 / 筛选 / 分页重复；改为在列表把人定到 1 个再进编辑，定位成本不随人数增长。
- **侧栏只保留一级模块**：不再为喂养师模块挂「↳ 档案编辑」等重复子项，模块内定位即可。
- **变更可解释**：保存前列出待保存改动（旧值 → 新值）与下游影响（停用 → AI 直接淘汰；等级 → 派单权重与高风险类目准入；抽成 → 下个结算周期；地址 / 档期 → 距离与时段判定），并支持「放弃修改」二次确认。
- **保存联动**：喂养师列表行、档案详情卡、喂养师端「我的档案」、✦ AI 派单判定、财务结算抽成、操作日志、localStorage 同源更新；校验拦截手机号、抽成范围、空姓名、空类目、地址经纬度、7 天时段与容量。
- **端侧权限**：喂养师端可改基础资料与常驻地址；认证等级 / 抽成 / 账号状态 / 每日档期由运营后台设定，端侧只读并可生成后台档案深链。

### 优惠券发放 —— 双通道（v1.2 补充）

- **后台直接发放 `push`**：运营选人群包 → 券直接进宠主「我的优惠券」+ 站内通知；用于会员权益、客诉补偿、沉默用户召回。无领取动作、无库存、无风控校验。
- **用户主动领取 `claim`**：运营只配置「领取入口 + 可领人群 + 每人限领 + 总库存 + 领取时间窗 + 分享券码 + 同设备风控」，用户到领券中心 / 活动落地页 / 分享链接 / 输入券码自助领取。
- **领取校验顺序**：券模板状态 → 时间窗 → 可领人群 → 每人限领 → 库存 → 风控 → 入账。任一不通过即在宠主端显示逐条淘汰原因与后续动作；通过后后台已领取数 +1、库存 −1、领取流水留痕。
- 两种类型**共用同一券模板**（面额、门槛、适用服务、有效期、核销），仅发放链路不同；支付页均可抵扣并实时改写实付金额。
- 券列表按发放类型区分操作（直接发放 →「发放」，用户领取 →「配置领取」）；宠主端新增「领券中心」屏，运营后台新增「发放类型 · 领取规则设定」卡片（切换联动、宠主端预览、规则说明、领取记录 / 风控流水）。

## 十、竞品分析与差异化方向（v1.1 新增）

> 对标竞品：**小布在家**（撮合制 · 宠托师自主报价）、**宠好伴**（深圳艾宠 · 平台派单 · 极速履约）、**牵爪**（标准化连锁 · 假期托管）。三者均覆盖深圳。

### 竞品对比要点

| 维度 | 暖爪 | 小布在家 | 宠好伴 | 牵爪 |
|------|------|---------|--------|------|
| 派单模式 | AI 自动派单 | 选人→报价→反选 | 平台派单 | 平台预约 |
| AI 报告 | ✅ 核心卖点 | ⚠️ 人工+AI质控 | ⚠️ 图文报告 | ❌ |
| 应急/送医 | ✅ 本次纳入 | ⚠️ 12h客服 | ✅ 24h应急 | ⚠️ |
| 异宠 | ✅ 本次纳入 | ✅ 小宠喂养 | ⚠️ | ⚠️ |
| 服务直播 | ✅ 本次纳入 | ✅ 10元/次 | ⚠️ | ❌ |
| 陪玩时长量化 | ✅ 本次纳入 | ⚠️ | ✅ ≥10分钟 | ⚠️ |

### 差异化方向（基于竞品空白 + 暖爪 AI 优势）

1. **AI 喂养报告（唯一）**：三竞品均无真 AI 报告，做成行业标杆。
2. **AI 派单"可解释理由"**：竞品均为人工/撮合，暖爪派单附带理由，宠主可查看。
3. **异常主动预警**：拒食/呕吐/受伤即时推送，竞品靠人工观察易漏报。
4. **进/出门实时提醒**：100% 触发，含时间戳，强化"全程可见"心智。

### 风险提示

- **巨头进场**：滴滴等已试点"上门喂遛"（统一接单/派单/购险/处理纠纷），路线与暖爪高度重合。暖爪须以 AI 差异化抢时间窗口，不拼运力。
- **不可抄**：自由报价撮合制（削弱自营品质可控）、宠托师收认证费（冷启动挡人）、全国快速铺开（应聚焦深圳单区）、多元业务（洗护/善后等分散精力）。
