# 暖爪 RAG 建设方案（工程说明，不入库）

> 2026-11-17 更新：初始向量检索选型方案已落实为 OpenAI 兼容 embedding + PostgreSQL pgvector 持久化索引，客服查询结合向量和关键词排序。已发布 11 篇、73 条问答。当前实现与验证方式以 `../README.md` 为准。

## 推荐起步方式

保留当前 FastAPI 服务和 `app/llm.py` 的聊天模型调用，新增独立的离线入库流程与 RAG 检索模块。先审核 Markdown 并建立可重复的索引构建，再把 `/api/ai/chat` 从直接生成切换为检索后生成。Embedding 把文本转成用于检索的数值向量，不是在训练聊天模型；当前依赖中没有 embedding 或向量库依赖。

先从一种向量存储开始。若本地原型要快速验证，可评估持久化 Chroma；若希望与业务 PostgreSQL 共管，可先验证服务器 PostgreSQL 是否已安装并允许 pgvector 扩展，再决定使用 pgvector。两者是选型，不是当前模块已经安装或配置的能力。避免为简单检索同时引入多个编排框架；当前已用 LangGraph，可先由现有图编排检索、回答节点。

模型可选本地 BAAI/bge-m3，或支持中文的云 embedding 服务。当前 `.env.example` 中的 Hualong/OpenAI 兼容配置只覆盖聊天补全，不代表 embedding 接口可用。选型需检查供应商的 embedding API、模型标识、维度、限流、数据处理条款，并在真实环境评测。同一集合必须使用一致的模型、维度、归一化和文本处理规则。更换模型需重新生成整套向量及索引。密钥通过服务端环境变量配置，绝不写入知识文档或前端。

## 离线入库流程

1. 仅读取 `documents/` 下 Markdown，解析 YAML 元数据。
2. 校验必填字段、唯一文档 ID、审核人及版本；正式索引只接受 `status=published` 且审核人非空的篇目。
3. 以二级标题分段，每个完整问答优先作为一个 chunk。把文档标题和小节标题加入检索文本，移除正文中的 YAML，但将其字段保存在 metadata。
4. 太长的小节再按模型 tokenizer 切分，初始可用约 300–600 token、重叠 50–100 token，并结合模型输入上限与检索效果调整。不要切断问题与简短答案，也不要把不同角色的规则合并。
5. 调用 embedding 模型生成向量，连同原文、文档 ID、版本、小节标题、角色、状态、源文件、内容哈希存储。
6. 使用稳定 chunk 标识进行 upsert。文档更新或删除时，移除该文档遗留的旧 chunk，避免新旧规则同时召回；更稳妥的上线方式是构建新集合并在验收后切换。
7. 记录模型标识、模型版本、向量维度、切分参数、语料版本和入库统计，支持回滚与排错。

初始版本全部篇目为草稿；2026-11-17 已对软件行为完成技术核对并扩充发布说明，核对性质和未确认政策见 `../README.md`。开发草稿仍只允许离线预览。

## 在线问答流程

用户消息 → Spring Boot 校验身份、会话与订单归属 → Python AI 服务（服务间鉴权）→ 使用可信服务端角色过滤发布知识 → 检索相关知识 → 按需获取授权的实时业务数据 → 大模型基于证据回答 → 返回答案和引用。当前 `/api/ai/chat` 的响应模型只有 `reply`，引用字段和可信角色传递协议尚未定义；实现 RAG 时应版本化请求/响应契约，并与 Spring Boot 联调，不要把用户可控的 `context` 当作授权凭证。

用户问题必须使用与入库一致的 embedding 模型编码。可先取约五个候选片段；若结果欠佳再加入关键词混合检索和 reranker。不要套用一个未经评测的通用相似度阈值，不同模型及距离度量的分数含义不同。

角色由已认证的服务端上下文决定，不能相信用户在提问里自称管理员。角色过滤应在检索查询阶段执行，不能先拿到内部资料再要求大模型隐藏。真实订单、地址、门锁信息等按需通过授权接口查询，不能混入共享向量集合。

答案需要标注实际使用的文档标题、小节与版本；无足够证据时说明无法确认并引导人工。检索到的文字是资料，不能作为系统指令执行。客服消息要求退款、取消或送医时，生成解释和执行业务操作应分开，操作继续遵守原有权限、确认和状态校验。

## 最小工程结构建议

后续可在 `5.ai/` 增加：

```text
app/                 # Python 服务、检索与模型封装
scripts/ingest.py    # 文档校验、切分、embedding、增量索引
scripts/evaluate.py # 检索与回答评测
knowledge/          # 当前已生成的文档
data/chroma/        # 本地持久化索引；加入忽略列表，不提交仓库
```

以上 Python 文件与数据库目录只是建议，当前尚未创建或运行。

## 验收

先用 `evaluation/questions.jsonl` 检查目标文档是否出现在候选结果中，再检查答案是否忠于依据、有正确引用，并能处理无答案、角色越权和实时数据问题。该样本仅用于起步，正式上线前补充真实问法、相近问题和反例。

同时验证：重复导入不重复、修改后旧内容不再召回、删除或撤回立即退出正式索引、宠主检索不到喂养师内部知识、未接实时接口不编造订单信息、未接真实支付不宣称已完成退款。
