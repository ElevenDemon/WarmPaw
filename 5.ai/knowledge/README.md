# 暖爪客服知识库

截至 2026-11-17，语料已从 5 篇、24 条问答扩展为 **11 篇、73 条问答**，通过 embedding + PostgreSQL pgvector 接入客服工作流。向量保存在独立 `ai_knowledge` schema；语义结果结合关键词 RRF 排序，并在数据库查询时按角色过滤。现有 Spring Boot 代理及 `{reply}` 响应保持兼容。

## 文件用途

- `documents/`：检索的唯一语料来源；每篇含 YAML 元数据，仅读取直属 Markdown。
- `planning/`：建设说明与待确认政策，不进入用户问答索引。
- `evaluation/questions.jsonl`：验收问题及预期行为，不进入知识索引。

## 当前版本与审核

本次 `published` 篇目包含已对照工作区实现核对的技术操作说明，以及不承诺平台承接能力的常规交接建议。`reviewed_by` 如实标注为 Codex 技术或边界核对，**不表示运营、兽医或法务已经审批**。原有五篇中的软件行为已复核并更新版本，同时纠正“AI 服务尚未建好”的过时描述。

退款比例、赔偿标准、保险、服务城市、客服时间、提现时限及失联授权等政策仍未确定，不因文档发布而视为生效；只能说明待核实边界。面向客户部署前，业务负责人应核实说明与部署版本、正式协议一致，需要变更时填写实际审核人及版本。

新增内容先设 `status: draft`，核对后设 `published` 并填写真实核对人；撤回使用 `archived`。涉及运营承诺的内容需要运营审核。草稿仅允许离线预览，线上没有草稿开关。

不得直接把整个项目目录递归入库：只选择 `documents/` 下符合发布条件的 Markdown。开发说明、评测题、密钥配置、真实订单、地址、门锁密码和个人病史都不属于公共知识语料。

## 元数据约定

`id` 是稳定文档标识；`version` 是内容版本；`audience` 指定适用角色；`status` 控制是否入库；`updated_at` 是内容更新时间；`reviewed_by` 是审核人；`sources` 指明核对来源。

每个 `##` 小节是一条完整问答，保留问题、答案、适用条件和处理边界。加载器校验 ID 唯一、必填字段、角色、状态、审核标记、空章节和章节长度。正式检索仅加载 `published` 且 `reviewed_by` 非空的文档。

## 检索、更新与验证

索引使用服务端配置的 OpenAI 兼容 `/embeddings` API。默认复用聊天模型 API 地址和密钥，可分别配置 embedding 地址、密钥及模型。向量索引保存文档 ID、标题、小节、版本、适用角色、来源与正文；账号数据不会写入知识向量库。检索先按 OWNER / SITTER 角色过滤，再融合语义和关键词排序，返回最多五条。短期记忆只使用同一客服会话中的最近 12 条消息，追问检索结合最近四条对话；上下文总长限制为 8,000 字符，且只保留近期历史。短期记忆不会跨会话，历史 AI 答复不能成为知识依据。模型提示要求按标题、小节、版本标注本次使用的资料；没有充分依据时说明无法确认。

每次入库按**语料正文 + embedding 服务地址 + 模型标识**生成稳定指纹。重复入库无需重新生成向量。所有向量先在连接外生成，之后在事务内完整替换配置的索引，事务失败会保留旧索引。当前方案采用单一索引原子替换，不保留历史代次；如需长期版本回滚，后续可加 active generation 指针。

首次建表由 `scripts/ingest_knowledge.py --init-db` 执行，其中包含 `CREATE EXTENSION vector` 和创建 `ai_knowledge` 专用 schema；执行账号需有扩展权限，pgvector 还必须预先安装在数据库服务器。之后日常入库**不需要**扩展创建权限。服务启动时验证当前语料对应的指纹和段数。**增删改、换 embedding 模型或撤稿后，先重新入库，再重启 Python 服务**。当前没有热更新或管理后台。`VECTOR_MIN_SIMILARITY` 默认 0.35，应使用已配置模型在真实问法上调校。

在 `5.ai` 目录、已安装项目依赖的 Python 环境运行：

```powershell
python scripts/evaluate_knowledge.py
python scripts/ingest_knowledge.py
python scripts/evaluate_knowledge.py --vector
python -m unittest discover -s tests -v
# 仅离线预览草稿，不影响线上：
python scripts/evaluate_knowledge.py --include-drafts
```

28 道检索题检查前五条是否包含预期文档、禁止文档是否被隔离及指定无答案题是否返回空结果；`--vector` 会调用配置的 embedding API 及 pgvector，不代表模型回答准确率。测试覆盖发布门槛、角色隔离、文档替换、重复 ID、短追问和外部证据注入过滤。模型理解与引用准确性仍需单独验收。

## 数据边界

知识库解释规则和操作方法。具体价格、账号会员状态、券是否可用、订单进度、喂养师位置、医院当前营业状态，应通过受权限控制的实时接口获取；接口未连接时明确无法查询，不从语料推测。

当前 AI 客服没有实时业务查询或执行工具，不代办退款、改期、取消、投诉或送医。角色来自 Spring Boot 登录态；Python 接口应仅向可信后端开放，生产设置 `AI_API_KEY` 并由后端以 `X-AI-API-Key` 调用。Python 本身不验证用户登录令牌，不能将其作为公开客户端接口。

服务模块现状及 RAG 接入建议见 `planning/AI服务与RAG接入.md`；索引设计见 `planning/RAG建设方案.md`；政策缺口见 `planning/待确认政策.md`。
